## 1. 产品目标

做一个在公司 Windows 浏览器中使用、无需安装客户端的 Word 文档对比与合并工具。

用户可以像阅读 VS Code 的左右 diff 一样，查看旧版与新版的对应内容和差异。对每一处差异，选择采用旧版还是新版，最后导出合并后的 Word 文件。

第一阶段聚焦英文 Word 文档的主体内容，包括正文和表格。内容检查与格式检查分开，优先实现内容比较。Excel 后续再考虑。

## 2. 已确认需求与设计理由

| 需求 | 具体约定 | 为什么这样做 |
|---|---|---|
| 使用环境 | 公司 Windows 浏览器；无需安装客户端 | 方便在工作环境中使用，减少安装与分发负担 |
| 界面语言 | 英文 | 与文档语言一致，便于不懂中文的同事使用 |
| 使用方式 | 首版为个人使用；不设计多人协作或审阅交接 | 先满足个人审阅场景 |
| 文档规模 | 十几页到 200 页以上；目前没有处理时间要求，但长文档需显示处理进度、界面不卡顿 | 覆盖实际文档范围 |
| 部署形态 | 文件只在用户浏览器本地处理，不上传服务器；可发布到 Posit Connect，也可作为单个 HTML 文件离线使用 | 文件不离开本机，合规风险最小；同一套产物两种用法 |
| Word 优先 | 先支持英文 .docx，包含表格；.doc 不支持；Excel 后续开发 | 聚焦主要使用场景，先保证一种文档的比较与合并可靠 |
| 左右对比 | 左边旧版，右边新版；对应内容对齐 | 直观看清修改前后内容，减少来回查找 |
| 统一阅读样式 | 两边使用同一套阅读样式，保留标题层级、列表、表格等结构 | 保持可读性，同时减少原始格式差异对内容审阅的干扰 |
| 内容与格式分开 | 分别检查、分别呈现；先实现主体内容比较 | 避免字体、间距等变化淹没内容修改 |
| 已有修订 | 两份上传文档均按接受全部已有 Track Changes 后的状态参与比较 | 为每份文件取得明确的内容状态 |
| 原文件不变 | 在内部工作副本上处理，不修改上传的原文件 | 保留原始文件及其历史 |
| 合并方式 | 每处差异选择“采用旧版”或“采用新版”，默认新版；任何选择组合都有效 | 与 VS Code diff 的使用习惯一致，选择之间不会互相冲突 |
| 导出底稿 | 以接受已有修订后的新版文件为底稿，只修改选择了旧版的位置 | 尽量保留新版的样式、结构和其他文档元素 |
| Clean 导出 | 优先开发；输出合并后的 Word，无未决修订 | 首先完成实际可用的工作闭环 |
| Track Changes 导出 | 后续开发；记录“新版 → 最终版”的变化；首版数据结构为此预留 | 让接收者查看本次审阅对新版做了哪些调整 |
| 导出样式 | 保留新版原有样式体系；不将网页统一样式写回 Word | 网页用于清楚阅读，Word 保持正式文档样式 |
| 批注 | 不比较；Clean 保留新版已有批注，不汇入旧版批注；批注锚点受合并影响时的处理以后再考虑。内容视图中显示新版批注的位置标记，只作提示（2026-10-07 决定） | 聚焦主体内容；选择前就能知道哪里挂着批注 |
| 未比较可见 | 不支持比较的元素必须在界面上可见，并标为“未比较” | “未比较”不能被误读为“无差异” |

## 3. 部署形态与技术方向

### 3.1 部署形态（已确认）

- 所有解析、比较、合并、导出都在浏览器本地完成，文件不上传。
- 同一份构建产物有两种用法：
  - 作为静态网页发布到公司 Posit Connect；
  - 作为单个 `.html` 文件分发，离线双击使用。
- 页面显示版本号。以 Posit Connect 上的版本为准，离线副本需自行替换为最新版本。
- 不依赖大模型做基础差异检测。

### 3.2 技术方向（建议，开发前确认）

- TypeScript + Vite + React。
- JSZip 读写 .docx；浏览器原生 `DOMParser`／`XMLSerializer` 操作 XML，未修改部分原样保留。
- 段落与表格行对齐使用自研算法：先按规范化文本序列对齐，再在变化区间内按相似度配对，处理改写、拆段、合段与移动。词级差异使用 jsdiff。
- 解析与比较在 Web Worker 中运行；长文档使用虚拟滚动；不使用 Monaco。
- 单文件构建，以支持离线使用。
- 自动化测试以 `testdocs/` 为黄金样例。

### 3.3 需要在公司环境确认

- 公司 Edge／Chrome 能否从本地打开含脚本的 HTML 文件。
- 通过邮件或 Teams 收到的 HTML 文件是否被拦截。
- Posit Connect 发布静态内容的权限。

## 4. “保留外观”的准确含义

### 4.1 对比界面：保留结构，使用统一阅读样式

用户需要的不是纯文本视图，也不是逐页、逐像素复刻 Word，而是保留适合阅读的文档结构。

| 原文内容 | 对比界面呈现 |
|---|---|
| Heading 1 | 统一的一级标题样式 |
| Heading 2 / Heading 3 | 对应层级的标题样式 |
| 正文段落 | 统一的正文阅读样式 |
| 编号和项目符号列表 | 保留条目、编号或符号及层级；编号按 Word 规则计算后显示 |
| 表格 | 保留行列、合并单元格关系，以表格呈现 |
| 上标、下标 | 照原样显示，**并视为内容** |
| 加粗、斜体、下划线 | 照原样显示，但视为格式，不参与内容比较 |
| 首版未比较的元素 | 以占位符显示，例如 `[图片 · 未比较]`，见 §6.3 |

网页上的字体、字号、颜色、段落间距不要求与原文件逐项一致。两边使用同一套阅读样式，便于比较。

为对应内容对齐，允许在显示中加入空白，不向原文件插入空段落。不要求网页分页和换行位置与 Word 完全相同。

### 4.2 内容检查与格式显示相互独立

在内容视图中显示标题或表格，不意味着当前正在检查其格式差异。

例如，两份文档标题文字一致，但从 Heading 1 改成 Heading 2：

- 内容比较不将其认定为文字修改。
- 后续格式／结构检查可以单独记录层级变化。
- 内容视图仍按各自的结构使用统一样式呈现。

格式功能尚未实现时，应显示“暂未支持”或“未检查”，不能显示“没有格式差异”。

### 4.3 导出 Word：保留基础文档样式

导出以新版文档为底稿，不用网页显示结果重新制作整份 Word。

只修改用户选择了旧版的内容，其余样式、结构和文档元素尽量原样保留。网页显示正确与导出文件正确需要分别验证。

## 5. 已有 Track Changes 的处理规则

1. 检测两份上传文件中的已有修订。
2. 在内部工作副本中按接受全部已有修订后的状态处理，包括内容修订和格式修订。
3. 对处理后的旧版与新版进行内容比较。
4. 上传的原始文件不变。
5. 上传文件中的旧修订历史不延续到本次生成的修订记录中。
6. 批注不因接受修订而被默认全部删除；批注比较不在当前范围内。

读取规则：

- 删除修订中的文字不读入。
- 移动修订只读入移动后的位置，不重复读取。
- 段落标记被删除时，该段与下一段合并。
- 被修订删除的表格行整行去掉，被修订插入的行保留。
- 格式修订直接采用当前格式。

界面固定说明：

> 已按接受全部已有修订后的文档进行比较，原文件未修改。

不需要每次弹窗确认。另外两条提示：

- **不支持的修订类型**：遇到尚不支持的修订类型（例如单元格级插入、表格属性修订）时：
  - 提示修订类型和位置；
  - 继续比较，不中断；
  - 在检查范围面板中列出，并说明附近结果可能不准确。
  - 支持和不支持的修订类型见 `docs/Supported-Scope.md`。
- **新版含未决修订**：导出时提示修订数量，例如“新版中 12 处未接受的修订将在导出文件中被接受”。因为新版中别人尚未接受的修订，导出后会被一并接受。

## 6. 比较范围与分阶段边界

### 6.1 第一阶段：主体内容

- 正文和标题文字的新增、删除、修改。
- 列表文字和条目增删（不含自动编号本身，见 §6.4）。
- 表格单元格文字修改；表格行增删；列和合并单元格的结构变化识别为“表格结构变化”。
- 段落及表格的对齐，包括改写、拆段、合段。
- 移动内容的识别（见 §7.4）。
- 上标、下标作为内容参与比较。
- 隐藏文字显示（虚线标注）并参与比较。
- 英文词级差异高亮。

### 6.2 后续范围

- 格式差异：字体、字号、颜色、段落间距、样式、标题层级、列表类型、表格格式等。
- Track Changes 导出。
- 页眉页脚、脚注、尾注、文本框、超链接地址、图片等元素的专门比较，按需要逐步扩展。
- 批注比较，以及批注锚点受合并影响时的处理。
- Excel 对比，单独设计工作表、单元格和记录匹配逻辑。

### 6.3 未比较元素的可见性

“未比较”不代表“无差异”。对支持范围以外的元素，不应在结果中暗示已完成全面检查。

- **占位符**：内容视图中，首版未比较的元素在原位置显示占位符，例如：
  - `[图片 · 未比较]`
  - `[脚注 2 · 内容未比较]`
  - `[文本框 · 未比较]`
- **检查范围面板**：顶部常驻，列出已比较的内容、未比较的元素及数量，以及“格式：未检查”。
- **指纹提示**：对未比较元素做“相同／可能不同”的简单判断，不展示具体差异。适用于页眉页脚、脚注内容、图片、超链接地址、文档属性。
- **页眉页脚按节提示**（2026-10-07 决定）：Word 的页眉页脚按节存放，每节最多有首页、奇数页（默认）、偶数页三种。
  - 逐节、逐种比较指纹，在检查范围面板中按节列出，例如“第 3 节 · 页眉 · 可能不同”。
  - 只在某一版中存在的节，标为“仅新版有此节”或“仅旧版有此节”。
  - 有差异的节在内容视图中加标记：第 1 节标在文档开头，其余各节标在前一节的分节符处。各节都相同时不加标记。

未比较的元素不应因此在导出时被自动删除。

### 6.4 可选比较项

以下内容由 Word 自动生成或动态计算，提供独立的“是否比较”开关。打开后，差异只做提示，**不可选择**采用旧版或新版。

| 项目 | 默认 | 首版 | 说明 |
|---|---|---|---|
| 自动编号（列表、标题编号） | 关 | 不实现，只显示编号 | 插入一条会使后续编号整体变化，比较时需标为“编号变化”并可一键隐藏 |
| 目录 | 关，目录区域折叠显示 | 实现开关 | 导出后需在 Word 中更新目录 |
| 日期、页码等域 | 关，只显示结果并标为域 | 实现开关 | 域结果会随打开时间、分页变化 |

手打的编号（例如 `1) `）是文字，按普通内容比较。

### 6.5 文本规范化

以下差异**默认全部显示**。每一类都单独标记，并可在查看选项中隐藏：

| 类别 | 示例 |
|---|---|
| 空白 | 多个空格与一个空格、不换行空格、段首尾空格、软回车与空格 |
| 空段落 | 空段落数量增减 |
| 引号 | 直引号与弯引号 |
| 短横线 | `-` 与 `–`、`—` |
| 大小写 | `Week` 与 `week` |

隐藏某类差异只影响显示和导航。被隐藏的差异仍按默认值（新版）进入最终结果。

## 7. 合并模型

### 7.1 差异片段与选择

比较结果是一串按顺序排列、互不重叠的片段。每个片段要么“相同”，要么“差异”。一个差异片段，是旧版中的一段连续内容（可以为空）对应新版中的一段连续内容（可以为空）。

用户对每个差异片段选择采用旧版或采用新版：

| 差异类型 | 旧版一侧 | 新版一侧 | 采用旧版 | 采用新版 |
|---|---|---|---|---|
| 修改 | 有 | 有 | 用旧版内容 | 用新版内容 |
| 新增 | 空 | 有 | 不出现 | 出现 |
| 删除 | 有 | 空 | 出现 | 不出现 |
| 移动 | 原位置 | 新位置 | 放回原位置 | 留在新位置 |

**最终结果 = 按顺序拼接各片段的取值。** 相同片段原样保留，差异片段按选择取值。任何选择组合都有效，不存在选择之间的冲突。

### 7.2 粒度

- 首版以**段落**为基本单位，相当于 VS Code 中的“行”。
- 表格内以**单元格**和**行**为单位。
- 每一对修改的段落是一个差异片段，段内以词级高亮显示具体变化（2026-10-07 决定：不再把连续修改的段落合成一个片段，以便分别选择）。
- 连续新增的段落合成一个差异片段；连续删除的段落同样合成一个。
- 拆段、合段（一对多、多对一）是一个差异片段。
- 数据结构预留段内词级选择，作为后续增强。
- 片段边界由对齐算法决定，首版不提供手动配对。

### 7.3 处理状态

- 每个差异片段有三种状态：**未处理**（按新版计算）、**已采用旧版**、**已采用新版**。
- 界面显示处理进度，例如“已处理 12／40”，并可跳到下一处未处理。
- 存在未处理项时仍可导出，导出前提示未处理数量。
- 选择记录支持撤销和重做。
- 已选择的差异可以恢复为未处理（Mark unreviewed）。
- 原始差异与用户的选择分开记录。改变选择后，差异仍可定位，可随时改主意。

### 7.4 移动内容

新版把一段内容从一个位置挪到另一个位置时，普通比较会显示成两处互不相关的差异（一处删除、一处新增）。分别选择可能导致内容重复或丢失。

规则：

- 识别“删除＋新增”中文字相同或高度相似的配对，标为“已移动”，合成**一个差异**。
- 一次选择：采用旧版即放回原位置，采用新版即留在新位置。两处的显示同步变化。
- 两处可以互相跳转。
- 移动的同时修改了文字时，两处都显示词级差异。

### 7.5 不可采用旧版的片段

旧版内容中的某些元素引用的是旧版文件内部的编号和关系，直接带入新版文件可能导致引用失效或文件损坏。

首版规则：

- 片段只含普通文字、上下标、制表符、软回车：可以采用旧版。
- 片段的旧版或新版任一侧含脚注或尾注引用、图片、超链接、域、文本框、嵌入对象（2026-10-07 决定：两侧都检查，从严）：
  - 照常显示差异；
  - “采用旧版”不可用，并说明原因，例如“此处含脚注，首版暂不支持带回，请导出后在 Word 中处理”。

以后逐步支持这些元素的迁移。

### 7.6 采用旧版时的格式与结构规则

- **修改片段**：保留新版段落的样式、编号和格式，只替换文字。带回的旧版文字继承新版相邻文字的格式，上下标除外（上下标随文字带回）。
- **删除片段采用旧版**（新版中已没有这段）：
  - 段落样式按样式名在新版中查找同名样式；
  - 找不到时，按大纲级别对应新版的标题样式；
  - 仍找不到时，用正文样式；
  - 列表项挂到新版中位置相邻、同层级的列表；
  - 直接格式不带回。
- **结构标记不随片段删除**：
  - 分节符转移到相邻保留下来的段落；
  - 文档末尾的节设置始终跟随新版；
  - 书签和批注的起止标记收缩到相邻位置，保证导出文件有效；
  - 域或内容控件的起止跨越片段边界时，该片段不可采用旧版，并说明原因。

具体样式继承细节在技术验证中确认。不应因合并一处内容而静默改变整份文件的样式或页面设置。

### 7.7 表格

| 变化 | 首版能力 |
|---|---|
| 单元格文字修改 | 单元格级二选一 |
| 行新增或删除（无合并单元格跨越该行） | 行级二选一 |
| 列新增或删除、合并单元格结构变化、嵌套表格结构变化 | 整张表二选一，并说明“表格结构变化，首版只能整表选择” |
| 段落与表格互换 | 整块二选一 |

表格行按内容相似度配对，不按行号配对。

## 8. 界面流程

本节按钮位置和细节通过原型验证。

### 8.1 选择文件

- 两个区域分别选择旧版、新版 .docx 文档。
- 显示文件名及版本角色。
- 支持交换左右文件。已有选择记录时，交换前需确认，交换后选择清空。
- 重新上传任一文件，同样需确认并清空选择。
- 显示已有修订的处理说明。
- 不支持的文件（.doc、加密文件等）给出明确提示。

### 8.2 阅读比较结果

| 区域或功能 | 内容 |
|---|---|
| 顶部 | 文件名、检查范围面板入口、内容／格式入口（格式显示“未检查”）、处理进度、导出操作 |
| 差异导航 | 上一处、下一处、下一处未处理、当前差异位置与总数 |
| 左侧 | 原始旧版内容，删除或被替换的部分高亮 |
| 右侧 | 原始新版内容，新增或替换后的部分高亮 |
| 最终结果预览 | 显示按当前选择拼接后的结果；第三栏和单栏切换两种方式都提供（2026-10-07 决定） |
| 查看选项 | 同步滚动、折叠相同内容、仅看差异、按类别隐藏差异（§6.5）、可选比较项开关（§6.4） |
| 合并操作 | 对差异片段选择“采用旧版”或“采用新版”，支持撤销和重做 |
| 批量操作 | 选定一节（默认当前差异所在的节，可从下拉中改选）全部采用旧版或新版；全部未处理项采用新版 |

- 左右两栏始终显示原始内容，不随选择变化。被放弃的一侧淡化，片段上标明当前选择。
- 删除使用红色，新增使用绿色，同时提供文字或图标标识，不仅靠颜色表达状态。
- 同步滚动以对应内容关系为依据，而不是机械地让两边滚动相同像素。
- 工具内不支持直接编辑文字。需要第三种写法时，导出后在 Word 中修改。

### 8.3 审阅进度

- 可随时导出审阅进度文件，内含两份文档的指纹和每处选择。
- 再次上传同样两份文件并载入进度文件后，恢复所有选择。
- 文件指纹不一致时，拒绝载入并说明原因。
- 存在未导出的选择时，离开或关闭页面前提示。
- 每次选择后自动保存一份到浏览器本地存储，作为辅助（2026-10-07 决定）。再次打开同样两份文件时，询问是否恢复。本地存储可能被清空，不作为唯一保存手段。

### 8.4 导出结果

- Clean：导出最终内容，无未决修订，保留新版已有批注。
- Track Changes：后续提供，以接受全部已有修订后的新版为基准，标记本次合并导致的变化。
- 导出为新文件，不覆盖上传文件。文件名为 `<新版文件名>_merged_YYYYMMDD.docx`。
- 导出文件设置为 Word 打开时提示更新域，使目录和交叉引用自动刷新。
- 导出前提示：未处理差异数量；新版中将被接受的未决修订数量。
- 导出后自检：工具重新读取导出文件，确认可解析，且内容与最终结果预览一致；不一致时警告。

## 9. 两种导出的具体示例

设旧版 A 为 12 weeks，新版 B 为 24 weeks，最终结果为 C。

| 用户选择 | Clean 导出 | Track Changes 导出（B → C） |
|---|---|---|
| 采用新版 | 24 weeks | 24 weeks，无本次新增修订 |
| 采用旧版 | 12 weeks | 删除 24，插入 12 |

必须区分：

- 屏幕上的版本比较：旧版 A 与新版 B。
- 修订版导出的比较基准：新版 B 与最终结果 C。

后续生成的修订表示本次合并，不代表原作者真实的历史编辑过程。

首版的修改计划需记录每处修改的位置、新版原内容和写入的旧版内容。Track Changes 导出只是把同一份修改计划写成修订标记，而不是直接替换。

## 12. 验收标准

1. 仅发生样式变化、文字未变时，内容比较不产生虚假的文字修改。
2. 同一段落因 run 拆分、换行或分页不同，不被误判为内容变化。
3. 新增一个段落后，后续相同内容仍能合理对齐。
4. 英文句子中仅一个词或数字变化时，能够清楚高亮实际修改；上下标中的变化同样能识别。
5. 表格保持表格呈现，能够识别单元格修改和行增删；结构变化时提供整表选择。
6. 上传文件已有修订时，比较结果基于接受全部修订后的内容。
7. 默认最终结果等于处理已有修订后的新版；全部采用新版时，导出内容与接受修订后的新版一致。
8. 选择与撤销仅改变选定片段。
9. 移动内容合成一个差异，任何选择都不产生重复或丢失。
10. 自动编号的顺延不被判为内容变化。
11. 采用旧版不破坏分节、页面设置、书签和批注结构；撤回含分节符的新增段落后，其余部分页面设置不变。
12. Clean 导出没有未决修订，保留新版已有批注与基础样式，并能被 Word 正常打开。
13. 后续 Track Changes 导出仅反映新版到最终版的差异。
14. 原始上传文件不变。
15. 未支持或未检查的内容有明确说明和占位，不被显示为“无差异”。
16. 审阅进度可保存并在同样两份文件上恢复。
