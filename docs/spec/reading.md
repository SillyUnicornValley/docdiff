# 读取 .docx 与已有修订

> 现行规则：能读哪些文件，已有修订怎么处理。
> 读取的技术细节见 [../implementation/stage2-design.md](../implementation/stage2-design.md) §2。

## 1. 支持的文件

| 文件 | 状态 | 说明 |
|---|---|---|
| `.docx`（Word 2007 及以后） | 支持 | |
| `.doc`（Word 97–2003） | 不支持 | 先在 Word 中另存为 `.docx`（File › Save As › Word Document）。由 Word 自己转换，内容、表格、已有修订、批注都保留，另存后可正常比较和导出；转换造成的 run 拆分、样式名不同不会被判为内容变化（决定 33） |
| `.docm`、`.dotx`、`.dotm` | 不支持 | 先另存为 `.docx` |
| 有密码或加密的文件 | 不支持 | 先在 Word 中去掉密码 |
| 限制编辑（没有加密）的文件 | 支持 | 限制设置保留在导出文件中 |
| Strict Open XML 格式 | 不支持 | 先在 Word 中另存为标准 `.docx` |
| 语言 | 英文 | 其他语言也许能用，但词级高亮是按英文设计的 |

不支持的文件在选择时给出明确提示。

## 2. 处理原则

1. 检测两份上传文件中的已有修订。
2. 在内部工作副本中按**接受全部已有修订**后的状态处理，包括内容修订和格式修订。
3. 对处理后的旧版与新版进行内容比较。
4. 上传的原始文件不变。
5. 上传文件中的旧修订历史不延续到本次生成的修订记录中。
6. 批注不因接受修订而被删除；两版批注在 Other parts 中逐条对比（[comparison.md](comparison.md) §5）。

实现上，接受修订是在 XML 副本上真正执行的，比较和导出用同一棵 XML，不需要换算位置（决定 22）。

## 3. 读取规则

- 删除修订中的文字不读入。
- 移动修订只读入移动后的位置，不重复读取。
- 段落标记被删除时，该段与下一段合并。
- 被修订删除的表格行整行去掉，被修订插入的行保留。
- 格式修订直接采用当前格式。

## 4. 修订类型逐项

所有修订都按“接受”处理，没有跳过不读的。区别只在于接受后的结果是否可靠（决定 34）。

| 修订类型 | 状态 | 说明 |
|---|---|---|
| 插入、删除文字 | 支持 | |
| 插入、删除段落 | 支持 | |
| 删除段落标记（两段合并） | 支持 | |
| 移动文字和段落 | 支持 | |
| 格式修订（文字和段落） | 支持 | 采用当前格式 |
| 插入、删除表格行 | 支持 | |
| 表格属性修订（列宽、边框、行高等） | 支持 | 采用当前属性；属于格式，不影响内容比较 |
| 分节和页面设置修订（纸张方向、页边距等） | 支持 | 采用当前设置；属于格式，不影响内容比较 |
| 插入、删除、合并单元格 | 接受，但会提示 | 接受后表格的列可能对不齐，这张表的比较结果可能不准确；在界面上报告（见 §5）。以后再做接受后的表格结构修正 |
| 列表编号修订 | 接受，元素本身未比较 | 自动编号本身不比较（[comparison.md](comparison.md) §6） |
| 文本框、页眉、页脚、脚注中的修订 | 支持 | 接受后的内容在 Other parts 中对比（[comparison.md](comparison.md) §5）；导出时同样接受 |

## 5. 界面提示

固定说明（不需要每次弹窗确认）：

> 已按接受全部已有修订后的文档进行比较，原文件未修改。

另外两条提示：

- **单元格修订**（插入、删除、合并单元格）：
  - 提示修订类型和位置；
  - 继续比较，不中断；
  - 在检查范围面板中列出，并说明这张表的结果可能不准确。
- **新版含未决修订**：导出时提示修订数量，例如“新版中 12 处未接受的修订将在导出文件中被接受”。因为新版中别人尚未接受的修订，导出后会被一并接受。
