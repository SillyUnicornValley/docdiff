# Stage 3 技术方案：导出 Clean .docx

2026-10-08。原则沿用 `stage2-design.md` §5 和 spec/export §1–§2。用户授权由开发方决定 Stage 3 的问题并记录（“you decide if any questions - and document your decisions”）。本阶段的决定是 `docs/decisions.md` 第 24–31 条，本文写明细节和理由。

## 1. 整体流程

```
用户点 Export
  → 重新读取两份原文件（得到新的 XML 副本，导出可以反复做）
  → 核对文件指纹与比较时一致
  → 以“新版 + 接受全部已有修订”的 XML 为底稿，只处理选了 Use old 的差异：
       修改的段落  → 原地改文字（§2）
       带回旧内容  → 复制旧版节点，放到对齐的位置（§3）
       删去新内容  → 删除节点，保护书签、批注和分节（§4）
  → 页眉、页脚、脚注、尾注、批注中的已有修订也全部接受（§5）
  → settings.xml 设置“打开时更新域”
  → 打包为 .docx（未改的部件原样复制）
  → 自检：重新读取导出文件，与最终结果预览逐块比较（§6）
  → 通过：下载；不通过：显示哪里不一致，由用户决定是否仍然下载
```

代码在 `src/engine/export/`：`exportDocx.ts`（流程）、`paragraphEdit.ts`（§2）、`importOld.ts`（§3）、`structure.ts`（§4）、`selfCheck.ts`（§6）。导出在主线程运行（需要 `DOMParser`）。07 长文档（75 处全部采用旧版）在浏览器中约 0.13 秒。

## 2. 修改的段落：原地改文字（决定 24）

规则：保留新版段落的属性、编号和没变的文字（连同其格式），只把变化的地方换成旧版文字。

- 旧版文字**替换**新版文字时，沿用被替换文字的格式。例：新版 “**24** weeks”（24 加粗）→ 旧版 “12 weeks”，导出为 “**12** weeks”。
- 旧版文字是**纯插入**时，沿用前面相邻文字的格式（段首则沿用后面的）。
- 上标、下标、隐藏文字属于内容，跟随旧版（spec/export §2）。例：新版 “m2” → 旧版 “m²”，导出的 2 是上标。
- 书签、批注范围等标记留在原处。例：批注锚在 “24 weeks” 上，改回 “12 weeks” 后批注仍然锚在 “12 weeks” 上（testdocs 05 的批注 c1，决定 8）。

做法：把段落中有文字的 run 拆成每字一个 run，按“词、空白、标点”逐个比较新旧文字，删去多出的字、插入缺少的字，最后把格式相同的相邻 run 合并回去。内容控件、智能标记里的文字同样处理（11 号文档的复选框、下拉框）。

## 3. 带回旧版内容（决定 25、26）

适用于：删除的段落、移动差异的“放回原位”、拆段合段、段落↔表格互换、整表差异、表格的增删行。

位置：放在对齐结果中该差异前一个片段之后；前面没有内容时放在后一个片段之前。

**单独带回的段落（决定 25）**

| 项目 | 规则 | 理由 |
|---|---|---|
| 段落样式 | 新版中同名样式 → 新版中同一大纲级别的标题样式 → 默认样式（Normal） | spec/export §2。按名字而不是按 id 找：德语等其他语言的 Word 中，“heading 1” 的 id 是 `berschrift1` 之类（08 号文档测试这一点） |
| 列表 | 挂到前后相邻、属于新版的列表上（保留旧的层级）；没有相邻列表时，新版中有完全相同定义的同一列表就沿用，否则去掉编号 | spec/export §2。不复制旧版的列表定义，避免往新版里加编号定义 |
| 段落直接格式（缩进、对齐、底纹等） | 不带回 | spec/export §2，让带回的段落和周围一致 |
| 文字格式 | 保留加粗、斜体、下划线、删除线、大写类；字体、字号、颜色不带回 | “**Note:**”、“**must not**” 的加粗往往有含义，这些格式不引用其他部件，带回是安全的；字体颜色是排版，跟随新版 |
| 上标、下标、隐藏 | 跟随旧版 | 属于内容（决定 4、11） |

**带回的表格和表格行（决定 26）**：保留旧版的表格布局（列宽、边框、合并单元格、底纹）和单元格内的段落格式，样式同样按名字找。理由：表格去掉布局就无法阅读；表格行要和同一张表的其他行对齐，必须带着自己的单元格设置。

**一律不带回**：旧版的书签、批注、分节设置、修订痕迹，以及非 Word 主命名空间的属性（如 `w14:paraId`，避免与新版重复）。图片、脚注、超链接、域在 Stage 2 已禁止 Use old（决定 15），导出时再次核查，出现即报错。

## 4. 删去新版内容时的保护（决定 27、28）

**书签和批注（决定 28）**：被删内容中的书签、批注起止标记和批注引用，移到前面最近的保留段落末尾（前面没有则移到后面最近的保留段落开头），保持原来的先后顺序。这样批注范围只会缩小，新版的批注不会丢失；交叉引用指向的书签仍然存在。表格单元格内的内容只在本单元格内找。

**分节（决定 27）**：被删的段落带着分节符时，分节设置不随之消失：
- 移到本节最后一个保留的段落上；
- 本节已经没有任何保留的内容时，这一节消失；
- 最后一节如果被删空，全文最后的页面设置取自前一节。

例（testdocs 05）：新版新增 “End of main protocol.”（带分节符，纵向）和横向附录。两处都采用旧版后，导出文件只有一节、纵向——不会出现“全文变横向”。只删分节段落、保留附录时，附录仍是单独的横向一节。

旧版的分节设置从不带回（spec/export §2：页面设置跟随新版）。

**其他**：单元格被删空时补一个空段落（Word 要求）；表格的行全部删去时删除整张表；块级内容控件被删空时删除控件。

## 5. 文件其他部分（决定 29）

- Clean 表示文件中没有任何未决修订：除正文外，页眉、页脚、脚注、尾注、批注中的已有修订也一并接受。导出前的提示数字只统计正文的修订（与比较时一致）。
- `settings.xml` 加 `w:updateFields`，Word 打开时提示更新域，目录、交叉引用、SEQ 编号随之刷新。
- 样式、编号定义、图片、页眉页脚（除接受修订外）等部件按原样复制。全选新版时，导出的 `document.xml` 与新版（接受修订后）逐字节相同（真实样例 DMP 已验证）。
- 文件名 `<新版文件名>_merged_YYYYMMDD.docx`（spec/export §1）。

## 6. 自检（决定 30）

导出后立即用同一个读取器重新读取导出文件，与“最终结果预览”逐块比较（文字和上下标等内容标记；格式和编号标签不算内容），并确认文件中没有残留修订。

- 一致：直接下载，提示 “Self-check passed”。
- 不一致或无法读取：**先不下载**，对话框列出不一致的块数和前几处示例（“仅预览中有 / 仅文件中有”），用户可选 “Download anyway” 或取消。理由：需求要求“不一致时警告”；先警告再下载，用户才不会在不知情时拿到有问题的文件。

## 7. 界面（决定 31）

- 导出对话框沿用原型：Clean 可用，Tracked changes 仍标为以后的版本。
- 新增两行说明：“带回的旧文字使用周围新版的格式”“写完后会重新读取并核对”。
- 导出过程中按钮显示 “Writing and checking…”。失败时显示原因，可重试。
- `?mock` 模式没有真实文件，导出仍是模拟，对话框注明。

## 9. 已知限制

- 段内只能整段取舍（G6）：导出也是整段改回旧版。
- 带回的列表项找不到相邻列表、而旧列表定义在新版中不存在时，会失去编号（08 号文档 “You feel unwell.”）。
- 复制的旧版表格如果引用了新版没有的表格样式，只保留直接设置的边框和底纹。
- Track Changes 格式的导出仍未实现（spec/export §1 “后续提供”）。
