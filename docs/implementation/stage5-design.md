# Stage 5 技术方案：扩展检查

2026-10-10。用户要求开始 Stage 5，并授权“有问题先自行决定”。本阶段的决定是 `docs/decisions.md` 第 41–46 条，本文写明细节和理由。

> **v0.5.1 更正（决定 47）**：M3 格式检查已撤回，代码已删除，Formatting 标签页恢复为 “not checked”。用户本来打算以后单独做格式检查（内容、格式各出一套结果，可只看其一或同时显示），一起显示会让比较页面太拥挤。§4 保留撤回前的设计，以后做格式检查时参考。原则不变：默认结果 = 新版；不确定就不做；看不到的要说出来；导出必须自检。

## 1. 范围与顺序（决定 41）

Stage 5 在 [scope §4](../spec/scope.md) 中列了五项。按“对合并结果的影响”排序，分五个里程碑：

| 里程碑 | 内容 | 能否选择 | 影响导出 |
|---|---|---|---|
| M1 | 段内逐处选择（G6 的“段内展开”） | 能 | 是 |
| M2 | 带回含脚注、超链接、域、图片、公式的旧版内容 | 能（解除部分 Use old 限制） | 是 |
| M3 | ~~格式检查（含列表类型）~~ 已撤回（决定 47） | — | 否，保留新版格式 |
| M4 | 其他部分逐项比较：脚注尾注文字、页眉页脚、文本框、超链接地址、图片、文档属性 | 只提示 | 否 |
| M5 | 批注比较，以及 Use old 对新版批注的影响提示 | 只提示 | 否，仍只保留新版批注 |

为什么 M3–M5 只提示、不能选择：导出以新版为底稿（决定 24–26）。把旧版的格式、页眉、脚注文字、批注写回新版，每一项都要单独的写回规则和自检，风险和工作量都大；而“看出来哪里不同”已经解决了用户最担心的漏看问题。和标题级别（决定 37）、自动编号（决定 38）一样：先提示，需要改的导出后在 Word 中改。以后真有需要，再逐项做成可选择的差异。

版本号：v0.5.0（跳过 v0.4，因为 Stage 4 暂缓）。引擎版本 engine-5（差异编号算法不变，旧进度文件仍可载入；只是 Use old 可用范围变了，词级差异多记了位置）。

## 2. M1 段内逐处选择（决定 42）

### 2.1 规则

- 适用：一对一的“修改”段落（正文或单元格里的段落），段内有 **2 处或以上** 词级变化，且可以 Use old。拆段、合段、移动、整表差异不适用。
- 默认仍是整段一个差异（G6 不变）。卡片上多一个按钮 “Choose per change (N)”，展开后逐处列出：`“12” → “24”  [Old] [New]`。
- 只要有一处选了旧、一处选了新，状态就是 **Mixed**（算已处理）。所有处都选同一边时，自动变回整段的 Use old／Use new。
- 整段按钮（Use old / Use new、快捷键 1 / 2、批量操作）照旧，会覆盖逐处选择。
- 撤销、重做、进度文件、浏览器自动保存都包含逐处选择。进度文件 `formatVersion` 升为 2，仍能读 1。
- 被隐藏类别的那几处（例如只是空白变化）在展开列表中也列出，标上类别，默认随整段。
- 最终结果预览显示拼出来的段落，来自旧版的那几处用琥珀色标出。

例：01 号文档 “Weeks 2, 4, 8 and 12” → “Weeks 2, 4, 8, 12, 16 and 24”。词级变化有两处：“ and 12” ↔ “, 12, 16”、“ and 24” 的新增部分。用户可以只保留新版加的 16、24 中的一处。可能拼出不通顺的句子——这是用户的选择，预览里看得见。

### 2.2 实现

- `WordHunk` 新增 `at: { old, new }`：这处变化在旧、新段落中的起始位置。纯插入或纯删除时另一侧没有文字，没有位置就拼不出结果，所以必须记录。
- `ReviewState.choices` 的值从 `Choice` 扩展为 `Selection = Choice | { hunks: Choice[] }`（`src/model/review.ts`）。
- `src/model/mixed.ts`：按逐处选择拼出段落（`ParagraphBlock`），只含文字、制表符、换行（Use old 可用意味着段落里没有其他元素）。新版批注标记保留在原位置。
- `buildFinal` 输出拼出的段落；导出时 `ParagraphEditor.rewrite` 以拼出的段落为目标原地修改新版段落（决定 24 的格式规则不变：没改的字保留新版格式）。自检照常比较。

## 3. M2 带回含其他元素的旧版内容（决定 43）

### 3.1 规则

Stage 3 中，片段任一侧含脚注、尾注、图片、超链接、域、文本框、嵌入对象就不能 Use old（决定 15）。Stage 5 解除其中可以安全写回的部分：

| 元素 | Stage 5 | 怎么写回 | 仍然不可用的情况 |
|---|---|---|---|
| 超链接 | 可用 | 复制旧版链接地址，新建关系（rId） | — |
| 域（交叉引用、日期、页码、SEQ…） | 可用 | 域代码原样带回，导出打开时更新域 | 引用的书签在新版中不存在（REF、PAGEREF、NOTEREF） |
| 脚注、尾注 | 可用 | 旧脚注内容复制到新版脚注部件，重新编号 | 新版没有脚注（尾注）部件；脚注里有图片等引用其他部件的内容 |
| 图片（普通图片） | 可用 | 图片文件复制进新版，新建关系，图片编号去重 | 链接到外部文件的图片 |
| 公式 | 可用 | 原样带回（不引用其他部件） | — |
| 图表、形状、SmartArt、文本框、嵌入对象、嵌入文档 | 仍不可用 | — | 牵涉多个部件（图表数据、OLE 二进制、文本框中的内容），写回出错的代价大 |
| 跨片段边界的域、内容控件 | 仍不可用 | — | 同 Stage 3 |

只有新版一侧含这些元素时（例如新版给某段加了脚注，用户要旧版）也解除：新版的脚注引用随文字一起去掉。脚注部件里留下没有引用的脚注，Word 不显示，也不报错。

### 3.2 修改段落的写回

决定 24 的“原地改文字”只适用于纯文字。段落任一侧含上表中的元素时，改为 **整段替换内容**：

- 保留新版段落的段落属性（样式、编号、缩进等）；
- 段落内容换成旧版的内容（文字只保留加粗、斜体等简单强调，同决定 25）；
- 新版段落里的书签、批注标记保留：原来在文字前面的放回段首，其余放到段尾，批注范围因此可能变大到整段，但不会丢失。

代价：这一段中没有变化的字也换成旧版的文字格式。可以接受：这种段落本来就少，而且内容正确优先。

### 3.3 自检加强

自检除了比较文字，也比较脚注（尾注）文字、图片内容和超链接地址的指纹：带回的脚注文字、图片必须和旧版一致。

## 4. M3 格式检查（决定 44，已撤回，见决定 47）

> 以下是撤回前的设计和实现，代码已在 v0.5.1 删除（原文件：`src/engine/docx/formatting.ts`、`src/engine/compare/formatting.ts`、`src/ui/FormattingTab.tsx`，可在 git 提交 `54ae2fb` 中找到）。以后做格式检查时可以参考比较范围和“按生效格式比较”的做法；呈现方式要按决定 47 重新设计。

### 4.1 比较什么

只比较**配对的段落**（相同、修改、移动的段落，包括表格里的）和配对的表格。新增、删除的内容没有对应的另一边，不比较格式。

| 类别 | 属性 |
|---|---|
| 段落 | 样式名、对齐、缩进（左、右、首行）、段前段后间距、行距 |
| 列表类型 | 项目符号 ↔ 编号、编号格式（1. ↔ a. ↔ i.） |
| 文字 | 加粗、斜体、下划线、删除线、大写、字体、字号、颜色、突出显示 |
| 表格 | 表格样式名 |

- 比较的是**最终生效的格式**：直接格式 → 字符样式 → 段落样式（含 basedOn 链）→ 文档默认值。这样 “样式里加粗” 和 “直接加粗” 不会被误报为不同。
- 文字格式只在两边相同的词上比较（改动的词是内容差异，已经高亮）。
- 标题级别变了的段落不列入格式（⚑ 已提示，其样式带来的字号、颜色变化也不重复）。自动编号（№）照旧提示；两段都是列表项而列表类型不同时，格式中另报“List type”。

### 4.2 呈现

- **Formatting** 标签页不再是 “not checked”，而是逐条列出格式不同的段落：位置（所在章节）、文字开头、每项属性 “Bold: off → on · ‘Weeks 2, 4’”。点击跳到 Content 视图中的该段。
- Content 视图中，格式不同的段落旁显示 “Aa” 标记，悬停看具体属性。View 菜单 “Mark formatting changes” 默认勾选，可取消。
- 只提示，不能选择，导出保留新版格式。

## 5. M4 其他部分逐项比较（决定 45）

新增 **Other parts** 标签页，逐项比较原来“只检测”的部分：

| 部分 | 配对方法 | 显示 |
|---|---|---|
| 脚注、尾注 | 按出现顺序；文字完全相同的先配对，其余按顺序配对 | 旧、新文字并排，词级高亮 |
| 页眉、页脚 | 沿用按节配对（决定 17），逐节、逐种 | 同上 |
| 文本框 | 按出现顺序，同脚注 | 同上 |
| 超链接地址 | 配对段落中按顺序配对的超链接 | 显示文字、旧地址 → 新地址 |
| 图片 | 配对段落中按顺序配对的图片 | “图片内容不同”，不显示图片 |
| 文档属性 | 标题、主题、说明、关键词、类别 | 旧值 → 新值 |

- 只列出不同的项，并给出“N 项相同”的计数。
- 只提示，不能选择，导出保留新版。
- 检查范围面板中这些元素的状态从“只检测”改为“比较（只提示）”。

## 6. M5 批注（决定 46）

- 旧版批注也读入，在旧版一侧显示位置标记（灰色，“Old comment · 作者”）；新版批注照旧。
- Other parts 标签页的 Comments 一节逐条比较批注：按（作者、批注文字）配对，再按锚定文字配对。状态：相同、批注文字改了、锚定文字改了、只在旧版、只在新版。
- 导出仍只保留新版批注，不带入旧版批注（决定 8、19 不变）。导出对话框提示：有 N 条新版批注锚在你选了 Use old 的内容上，导出后到 Word 中检查。

## 8. 已知限制

- 格式不检查（决定 47）；页眉页脚、脚注文字、文档属性、批注只提示，不能选择旧版（决定 41）。
- 修改段落任一侧含脚注、链接、域、图片或公式时，采用旧版是整段替换内容：这段中没变的字也换成旧版的（简化后的）文字格式；新版批注范围可能扩大到整段。
- 交叉引用指向的书签只在旧版、而且和交叉引用一起被删的内容里时，仍不能带回（书签不随内容带回，决定 26）。
- 脚注、文本框在空位中按文字相似度配对（不低于 0.4），没配上的显示为“只在一边”。
- 页眉页脚、文档属性中的 Title 通常随文件名变化，会列为不同。
- 仍未在 Windows Word 中实际打开导出文件（见 overview §4.3）。
