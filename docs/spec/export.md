# 导出

> 现行规则：导出的文件长什么样、选了旧版的地方怎么改、怎么保护文件结构。
> 实现细节和测试见 [../implementation/stage3-design.md](../implementation/stage3-design.md)。

## 1. 导出原则

- 以**接受全部已有修订后的新版**为底稿，不用网页显示结果重新制作整份 Word。只修改选择了旧版的内容，其余样式、结构和文档元素尽量原样保留。网页显示正确与导出文件正确需要分别验证。
- **Clean**：导出最终内容，无未决修订（正文以外的页眉、页脚、脚注、尾注、批注中的已有修订也全部接受，决定 29），保留新版已有批注，不带入旧版批注（决定 46）。选了旧版的内容上挂着新版批注时，导出前提示数量，提醒到 Word 中检查批注的位置。
- 格式不检查（决定 47），导出保留新版格式；页眉页脚、脚注文字、文档属性等只提示的不同（决定 45）不影响导出：一律保留新版。
- **Track Changes**：暂缓（Stage 4，决定 39），以接受全部已有修订后的新版为基准，标记本次合并导致的变化，见 §3。
- 导出为新文件，不覆盖上传文件。文件名为 `<新版文件名>_merged_YYYYMMDD.docx`。
- 导出文件设置为 Word 打开时提示更新域，使目录和交叉引用自动刷新。
- 导出前提示：未处理差异数量；新版中将被接受的未决修订数量。
- 导出后自检，见 §4。

## 2. 采用旧版时的格式与结构规则

总原则：不能因为合并一处内容，就静默改变整份文件的样式或页面设置。

### 2.1 修改的段落（决定 24）

在新版段落上原地改文字：

- 段落属性、编号、未改动文字的格式都保留；
- 替换进来的旧文字沿用被替换文字的格式，纯插入的沿用前面文字的格式；
- 上下标、隐藏文字跟随旧版；
- 书签和批注标记留在原处。

### 2.2 单独带回的旧段落（决定 25）

新版中已经没有这段，需要为它决定样式：

- 样式按名字在新版中找，找不到用同级标题样式，再找不到用默认样式；
- 列表项挂到相邻的新版列表，否则沿用定义完全相同的列表，否则去掉编号；
- 段落直接格式不带回；
- 文字只保留加粗、斜体、下划线、删除线、大写类，字体、字号、颜色不带回。

### 2.3 带回的表格和表格行（决定 26）

保留旧版的表格布局（列宽、边框、合并、底纹）和单元格内段落格式，样式按名字映射。旧版的书签、批注、分节设置、修订一律不带回。

### 2.4 结构标记不随内容删除（决定 27、28）

有些文档级结构挂在普通段落上。例如 05 号文档：新版在新增的 `End of main protocol.` 段落上挂了分节符，后面跟横向附录。如果用户把附录和这一段都选回旧版（即删掉），分节符随段落消失，而文档末尾的节属性仍是“横向”，结果整份文档变成横向。因此：

- **分节设置**移到本节最后一个保留段落；本节没有保留内容时这一节消失；最后一节被删空时，全文最后的页面设置取自前一节。旧版的分节设置从不带回。
- **书签和批注标记**移到前面最近的保留段落末尾（没有则移到后面最近的保留段落开头），保持顺序；批注范围只缩小，不丢失。
- **域或内容控件**的起止跨越片段边界时，该片段不可采用旧版（见 [merge.md](merge.md) §3）。

### 2.5 带回含脚注、超链接、域、图片、公式的旧内容（决定 43）

- **超链接、图片**：旧版文件里的链接地址、图片文件复制进新版，建立新的关系编号；图片文件名为 `docdiffN.<扩展名>`，必要时补上文件类型声明；图片编号（`wp:docPr`）重新编号，避免重复。
- **脚注、尾注**：旧脚注的内容复制进新版的脚注部件，用新的编号；样式按名字映射（同决定 25）；脚注里的链接、图片同样复制。新版没有脚注部件时不能采用旧版（[merge.md](merge.md) §3）。
- **域**：域代码原样带回，打开时更新域（§1）。
- **公式**：原样带回。
- **修改的段落**任一侧含这些元素时，不再逐字原地修改（§2.1），而是**整段替换内容**：保留新版段落的段落属性；内容换成旧版的（文字只保留简单强调，同 §2.2）；新版段落里的书签、批注标记保留，原来在文字前面的放回段首，其余放到段尾。代价：这段中没变的字也换成旧版的文字格式。
- **逐处选择的段落**（决定 42）：只含文字，仍按 §2.1 原地修改，只改选了旧版的那几处。

## 3. Clean 与 Track Changes 的区别

设旧版 A 为 12 weeks，新版 B 为 24 weeks，最终结果为 C。

| 用户选择 | Clean 导出 | Track Changes 导出（B → C） |
|---|---|---|
| 采用新版 | 24 weeks | 24 weeks，无本次新增修订 |
| 采用旧版 | 12 weeks | 删除 24，插入 12 |

必须区分：

- 屏幕上的版本比较：旧版 A 与新版 B。
- 修订版导出的比较基准：新版 B 与最终结果 C。

后续生成的修订表示本次合并，不代表原作者真实的历史编辑过程。

Clean 导出的修改计划记录了每处修改的位置、新版原内容和写入的旧版内容。Track Changes 导出只是把同一份修改计划写成修订标记，而不是直接替换，不需要重写比较和合并。

## 4. 自检（决定 30）

- 导出后，工具重新读取导出文件，确认可以解析，且内容与“最终结果”预览逐块一致。另外（决定 43）还核对脚注（尾注）文字、图片数据和超链接地址的指纹，确认带回的内容和旧版一致。
- 一致：直接下载。
- 不一致：先不下载，列出不一致的块数和示例，由用户选择 “Download anyway” 或取消。

## 5. 界面（决定 31）

- 沿用原型的导出对话框；Tracked changes 选项显示为以后的版本。
- `?mock` 模式下导出仍是模拟的。
